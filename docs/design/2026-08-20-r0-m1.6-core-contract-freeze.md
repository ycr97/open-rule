# OpenRule R0 + M1.6 Core Contract Freeze 技术设计

> 日期：2026-08-20
> 状态：Approved for implementation
> 前置：先提交或暂存当前 M1.5 工作，实施过程不得覆盖该工作树
> 范围：R0 工程基线、Definition Schema v2、Core 扩展/执行/值/超时契约及四个现有适配模块迁移

## 1. 交付目标

本批次结束后，OpenRule 必须形成可以稳定承载 M2c、M4、脚本与 EE 的 1.0 前最后一次 Core 大改：

```text
Definition v2
  → validate（完整报告）
  → compile（绑定 executor-owned immutable plan）
  → execute（只读输入 + 内部单线程状态 + absolute deadline）
  → immutable FlowResult
```

同时建立可重复的 Java 21/Maven/CI 基线，单元测试和 Docker IT 不再混用或静默跳过。

## 2. 非目标

- 不实施 M2c 的 head 表、草稿/发布事务、Flyway 和 Outbox；
- 不实现 DecisionTable、ScoreCard、Tree、RuleSet；
- 不增加 Redis、Micrometer、Groovy、JS、Python 或 EE 模块；
- 不实现决策包 ZIP、签名和 ReplayStore；本批次只冻结其依赖的 Core 契约；
- 不承诺兼容旧 Java API；必须兼容已持久化的 Definition JSON v1。

## 4. M1.6 目标架构

```text
API/Spring Map input
  → DecisionValues.fromJava
  → ExecutionRequest
  → OpenRuleEngine
       ├── FlowCompiler
       │    ├── NodeExecutorRegistry
       │    └── AggregatorRegistry
       └── FlowExecutor
            ├── ExecutionState (package-private)
            ├── NodeTaskCoordinator
            └── immutable FlowResult
```

### 4.1 新的包与类型

| 包 | 新增/替换类型 | 可见性 |
|---|---|---|
| `core.value` | DecisionValue 六种实现、DecisionValues、ValueLookup、ValueRef、ValueSource、JsonPointer | public |
| `core.id` | NodeTypeId、AggregatorId、FlowIdentity、NodeIdentity、PluginDescriptor | public |
| `core.definition` | SchemaVersions、FlowDefinition、StageDefinition、NodeDefinition、NodeConfig、AggregationDefinition、AggregationConfig、StageMode、StopPolicy | public |
| `core.validation` | ValidationIssue、ValidationReport、ValidationContext、DefinitionValidationException | public |

### 4.2 Definition Schema v2

完整最小示例：

```json
{
  "schemaVersion": 2,
  "flowId": "order-risk",
  "flowName": "订单风控",
  "version": 2,
  "aggregation": {
    "id": "openrule.priority",
    "configVersion": 1,
    "config": {}
  },
  "stages": [
    {
      "stageId": "base-risk",
      "stageName": "基础风险",
      "order": 10,
      "mode": "SERIAL",
      "stopPolicy": "SKIP_IF_STOPPED",
      "timeout": "PT3S",
      "nodes": [
        {
          "nodeId": "amount-limit",
          "nodeName": "大额限制",
          "type": "openrule.operator",
          "order": 10,
          "configVersion": 1,
          "config": {
            "left": { "source": "FACT", "pointer": "/order/amount" },
            "operator": "gte",
            "right": 1000
          },
          "decisionOnHit": "REJECT",
          "stopOnHit": true,
          "failPolicy": "ABORT",
          "timeout": "PT1S"
        }
      ]
    }
  ],
  "metadata": {}
}
```

规则：

- `schemaVersion` 必须为 2；只有 codec migrator 接受 v1。
- `enabled` 不属于 Definition v2；active 状态来自 Repository/FlowRevision。
- `version` 改为 long，0 仅允许 simulate/本地草稿，持久化版本必须大于 0。
- duration 使用 ISO-8601；0 或缺失表示使用 Engine 默认值，负数非法。
- metadata 仅用于标签和展示，不允许任何执行器或聚合器读取控制行为。
- JSON codec 必须开启 unknown-field failure、最大嵌套深度 64、最大文档 1 MiB。

### 4.3 v1 → v2 迁移

`FlowDefinitionJsonCodec.parse` 的顺序固定为 raw JSON 限额检查 → tree parse → schema detect → migrator chain → strict bind。

| v1 | v2 |
|---|---|
| 缺失 schemaVersion | `schemaVersion=2`（迁移后） |
| `aggregatePolicy=PRIORITY` | aggregation `openrule.priority` |
| `aggregatePolicy=FIRST_TERMINAL` | aggregation `openrule.first-terminal` |
| `nodeType=OPERATOR` | type `openrule.operator`，configVersion 1 |
| `operatorDef` | `config` |
| `leftFact=fact.a.b` | `left={source:FACT,pointer:/a/b}` |
| `leftFact=var.x` | `left={source:VARIABLE,pointer:/x}` |
| `executionMode` | `mode` |
| `skipWhenStopped=true` | `stopPolicy=SKIP_IF_STOPPED` |
| `skipWhenStopped=false` | `stopPolicy=RUN_AFTER_STOP` |
| `timeoutMillis=N` | `timeout=PT{N/1000}S` 的等价 ISO Duration |
| `enabled` | 丢弃；由数据库列或内存 revision 保存 |

以下 v1 内容不能安全迁移，必须返回明确错误：REGEX、Core 未实现的预留 NodeType、非 `fact.`/`var.` 的 leftFact 字面量、非 JSON-like rightValue、未知 aggregatePolicy。

JDBC 读取必须先对数据库中的原始 `definition_json` 校验原 checksum，再调用 codec；不得按迁移后的 v2 JSON 校验旧 checksum。

### 4.4 验证与编译

`FlowCompiler.validate` 不再遇到第一个问题就抛出。它返回按 path 排序的 ValidationReport：

```java
ValidationReport report = compiler.validate(definition);
CompiledFlowPlan plan = compiler.compile(definition); // report 有 ERROR 时抛异常并携带完整报告
```

ValidationIssue：

```java
public record ValidationIssue(
        String code,
        String path,
        Severity severity,
        String message) {}
```

固定结构校验：ID/名称长度、stage/node ID 全局唯一、order 冲突、duration、节点数量上限、并行上限、注册类型、config/plan 类型、聚合器存在。节点专属校验追加到同一报告，不得自行抛出无 path 的字符串异常。

compile 后 `CompiledFlowPlan` 只持有：

- FlowIdentity；
- 已解析 Engine contract/compiler version；
- 不可变 CompiledStage 列表；
- 已绑定 aggregation plan；
- 插件 requirements 清单。

运行热路径不得解析 JSON、读取 Definition、查 Registry 或访问 Spring 容器。

### 4.5 执行时序

```text
OpenRuleEngine.execute(plan, request)
  1. validate request + Engine open + bulkhead
  2. create request Deadline and package-private ExecutionState
  3. for each CompiledStage
       - stopped + SKIP_IF_STOPPED → StageResult skipped
       - freeze variables snapshot
       - submit each eligible node exactly once
       - await node/stage deadlines or ABORT
       - merge NodeResult by definition order
  4. build immutable AggregationInput
  5. aggregate once
  6. build immutable FlowResult
  7. observer/evidence hooks receive immutable completion event
  8. release bulkhead in finally
```

request deadline、调用方 interrupt、Engine closed 和 overload 不产生业务 Decision，抛出 Core 的 `RuleExecutionException`。Node/stage timeout 先形成 NodeFailure，再按 FailPolicy 生成继续、REVIEW、REJECT 或 ABORT 行为。

M1.6 的 purpose/effect 门禁固定为：LIVE 允许全部 effect；SIMULATE 禁止 WRITE_EXTERNAL；BACKTEST 只允许 PURE。M2d 提供 EvidenceAwareDataAccess 后，BACKTEST 才开放有完整回放证据的 READ_EXTERNAL。当前不满足的组合在提交节点任务前返回 `OR-EXECUTION-PURPOSE-UNSUPPORTED`。

### 4.6 Operator v2

Operator 在 compile 阶段完成：

- ValueRef/JSON Pointer 解析；
- operator 名称解析；
- right value 类型和 BETWEEN 边界检查；
- IN 集合复制与可选索引构建；
- 生成 OperatorPlan。

execute 只做 resolve + matcher，不创建 Pattern、不解析 BigDecimal、不做字符串隐式转换。M1.6 支持 ADR-0002 的运算集合，REGEX 从默认实现移除。

### 4.7 Spring/JDBC/API 适配

Spring 增加：

```java
public record FlowRevision(FlowDefinition definition, boolean active) {}
```

`FlowDefinitionRepository` 的查询/保存返回 FlowRevision，active 不再回写 Core Definition。M1.6 保持现有“save 自动启用”行为，仅完成数据模型分离；M2c 再把 save 改为草稿并引入 head 表。

`OpenRuleService`：

- `execute` 将 Map facts 转换为 DecisionObject，purpose=LIVE；
- `simulate` purpose=SIMULATE，version 可为 0，不写执行审计；
- FlowResult 自带 flow version，删除重复的 `ExecutionOutcome.flowVersion`；
- ExecutionLogger 改为只接收不可变 `ExecutionCompleted`，不得读取内部 Context。

API：

- HTTP JSON shape 尽量不变；
- 非法值、未知 type、迁移失败、validation report 分别映射稳定 400 错误；
- request timeout/overload 映射 503，执行 request timeout 映射 504；
- ABORT/engine invariant 映射 500；
- ExecuteResponse 增加 `flowVersion` 的来源改为 FlowResult，不增加重复字段。

JDBC：

- active 继续来自 `enabled` 列；
- aggregate_policy 列在 M1.6 停止作为执行数据源，仅为 v1 运维兼容保留；新写入内置聚合器分别投影为 `PRIORITY`/`FIRST_TERMINAL`，其他开放聚合器写 `CUSTOM`，执行时一律读取 definition_json；
- 新写 definition_json 统一 v2；旧行读取时迁移；
- checksum 仍覆盖原始 JSON 字节；读取校验在 decode 前完成。
- Core version 使用 long；M2c 将数据库 version 升为 BIGINT。在迁移前 JDBC adapter 对超出正 int 范围的版本返回 `OR-PERSISTENCE-VERSION-RANGE`。

|---|---|---:|

### 6.3 值与不可变性

覆盖 missing/null、1 与 1.0、"1"、NaN、Infinity、Set、非 String key、数组、嵌套 Map/List、源数据执行后修改、结果集合修改、JSON Pointer 转义和数组索引。

### 6.4 并发、Deadline 与取消

| 场景 | 验收 |
|---|---|
| 单线程有界 executor + Parallel | 无嵌套提交死锁 |
| 并行同 output key 1000 次 | 定义顺序决定最终值 |
| 并行变量读取 | 所有节点看到相同 stage-entry 快照 |
| node timeout 各 FailPolicy | SKIP/REVIEW/REJECT/ABORT 精确 |
| stage timeout | 仅未完成任务标记 stage timeout |
| request timeout | 无 Flow decision，整次失败 |
| caller interrupt | 中断位恢复，兄弟任务取消 |
| ABORT | 原因保留，迟到结果不合并 |
| bulkhead | 超额请求 fail-fast，无内部排队 |
| Engine close | 自有资源关闭，外部资源保留 |
| purpose/effect 组合 | 非法组合在节点提交前失败，外部调用次数为 0 |

测试优先使用 latch、barrier、手动 Ticker 和可控 executor；除验证真实调度集成外，不使用依赖墙钟的长 sleep。
