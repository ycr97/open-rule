# OpenRule M1.5 · Core 正确性加固 Session 记录

> 完成日期：2026-08-20
> 技术方案：`docs/plans/2026-08-20-openrule-m1.5-core-hardening.md`

## 一句话现状

M1.5 已完成：Compiler 下沉到 Core，新增 `OpenRuleEngine` Facade，修复 Parallel ABORT、`skipWhenStopped=false` 和深层不可变问题，编译产物与原始 Definition 解耦，补齐整体校验和 FirstTerminal 聚合；全 reactor 112 个非容器测试通过。

## 已完成能力

1. `FlowCompiler` 从 `openrule-spring` 移至 `openrule-core`，Spring Loader/Service 统一使用 Core Compiler。
2. 新增纯 Java `OpenRuleEngine`/Builder，默认装配 OPERATOR、PRIORITY、FIRST_TERMINAL 和 virtual-thread executor。
3. `CompiledNode` 在 compile 阶段绑定已解析 NodeExecutor；`NodeRunner` 不再依赖 Registry。
4. `CompiledFlow`/`CompiledStage` 保存执行标量和不可变列表；`CompiledNode` 保存 NodeDefinition/OperatorDef 快照。
5. Parallel Stage 将 ABORT 传播到调用方，并取消尚未完成的 CompletableFuture。
6. `skipWhenStopped=false` 可在 context 已停止后继续执行指定串行或并行 Stage。
7. `FactMap` 对 Map/List/Set/Collection/array 建立递归不可变快照。
8. 增加 flow/stage/node 空值、ID、order、executionMode、timeout 和节点专属校验。
9. 实现 `FirstTerminalAggregator`，并加入 Spring 和 Standalone 默认装配。
10. M1 Demo 改为使用 `OpenRuleEngine` 从 Definition 直接编译执行。

## 阶段 Review 结果

- 回归测试先复现 4 个缺陷：嵌套 facts 泄漏、串行 skip=false、并行 skip=false、Parallel ABORT。
- 1000 次并行同 key merge 均按定义顺序得到一致结果。
- 修正两处测试夹具问题：不可变测试误用 `Map.of`；缓存测试误用空流程。
- Core 源码扫描无 Spring/Jackson/JDBC/SLF4J 引用。
- Core compile dependency 仅 `org.projectlombok:lombok:provided`。
- `git diff --check` 通过，未发现遗留旧 Spring Compiler import 或旧 NodeRunner 构造链。

## 公共 API 变化

- 新增：`io.openrule.core.OpenRuleEngine`。
- 新增：`io.openrule.core.compiler.FlowCompiler`。
- 新增：`io.openrule.core.aggregate.FirstTerminalAggregator`。
- 迁移：删除 `io.openrule.spring.loader.FlowCompiler`，Spring 调用方改用 Core 包。
- 调整：`NodeRunner` 构造器由 `(NodeExecutorRegistry, ExecutorService)` 改为 `(ExecutorService)`。
- 扩展：`CompiledNode` 增加 executor 绑定能力。
