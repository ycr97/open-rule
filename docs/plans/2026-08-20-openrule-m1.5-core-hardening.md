# OpenRule M1.5 Core 正确性加固技术方案

> 日期：2026-08-20
> 范围：仅实施 roadmap 的 M1.5，不进入 M2c、M4、Redis 或脚本执行器
> 基线：M1/M2b 现有 90 个非容器测试通过，7 个 MySQL IT 因 Docker 未运行跳过

## 1. 目标与验收

本批次完成以下九项：

1. 将 `FlowCompiler` 从 `openrule-spring` 下沉到 `openrule-core`。
2. 新增纯 Java `OpenRuleEngine`/Builder Facade，直接支持 `validate → compile → execute`。
3. 修复 Parallel Stage 吞掉 `FailPolicy.ABORT`。
4. 修复 `skipWhenStopped=false` 无法执行的问题。
5. 将 `FactMap` 改为 JSON-like 嵌套结构的深层不可变快照。
6. 编译产物不再引用调用方可修改的 Flow/Stage/Node 集合与定义对象。
7. 增加 flow/stage/node 整体校验。
8. 实现 `FirstTerminalAggregator`。
9. 调整节点编译/执行关系，消除 `NodeRunner → NodeExecutorRegistry → RuleSetNodeExecutor` 构造链。

验收命令：

```bash
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home \
  mvn -B -ntp -pl openrule-core test

JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home \
  mvn -B -ntp clean verify

JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home \
  mvn -B -ntp -Pintegration -pl openrule-jdbc -am verify
```

## 2. 架构方案

### 2.1 Core 编译入口

新增 `io.openrule.core.compiler.FlowCompiler`。它负责：

- flow/stage/node 结构校验；
- 调用对应 `NodeExecutor.validate`；
- 按 stage/node order 稳定排序；
- 调用节点执行器的 compile 阶段；
- 生成与原始 Definition 解耦的编译快照。

Spring 只保留 `FlowLoader` 和 JSON Codec，统一依赖 Core 的 Compiler，避免同一套编译语义出现两份实现。

### 2.2 编译节点绑定执行器

`CompiledNode` 增加已解析的 `NodeExecutor`：

```text
FlowCompiler
  → Registry 解析 NodeType
  → NodeExecutor.compile
  → CompiledNode(definition snapshot, artifact, executor)
  → NodeRunner 直接调用 compiled.executor
```

`NodeRunner` 不再持有 `NodeExecutorRegistry`。未来 RuleSet 即使依赖 `NodeRunner`，也不会再形成 `NodeRunner → Registry → RuleSetExecutor → NodeRunner` 的构造环。

保留 `CompiledNode(NodeDefinition, Object)` 构造器供直接执行器单测兼容；经 `FlowCompiler` 生成的节点必须绑定 executor，未绑定节点交给 `NodeRunner` 时快速失败。

### 2.3 编译快照

- `CompiledFlow` 只保存 flowId、version、aggregatePolicy 和不可变 stage 列表。
- `CompiledStage` 只保存 stage 执行标量和不可变 node 列表。
- `CompiledNode` 保存 NodeDefinition 防御性副本；`OperatorDef.rightValue` 递归快照。
- 原始 Definition 及其集合在 compile 后被修改，不得影响编译结果。

### 2.4 停止语义

`skipWhenStopped=true`：进入 Stage 前 context 已 stopped 时跳过整个 Stage。

`skipWhenStopped=false`：即使进入 Stage 前已 stopped，仍执行该 Stage：

- SERIAL：忽略进入前的 stopped；若本 Stage 某节点新返回 `stop=true`，仍立即短路剩余节点。
- PARALLEL：所有节点按隔离模型执行，merge 后维持 stopped。

`NodeRunner` 增加内部的 `runWhenStopped` 执行参数；默认公开入口保持 stopped 即跳过。

### 2.5 Parallel ABORT

Parallel Stage 为每个 future 注册异常信号。任一节点按 ABORT 抛出时：

1. 取消其他未完成任务；
2. 解包 `CompletionException`/`ExecutionException`；
3. 将原 `RuleEngineException` 向 Flow 调用方传播；
4. 不生成伪造的普通失败 NodeResult。

Stage 整组 timeout 仍按现有约定转换为 skipped/failed 结果，不等同于 ABORT。

### 2.6 深层不可变 Facts

`FactMap` 对 Map、List、Set、Collection 和数组递归复制并包装为不可变结构；数组规范化为不可变 List。String、Number、Boolean、Enum 等标量按值保留。该模型与 JSON facts 一致，并保证源对象及读取到的嵌套集合均不能反向修改执行快照。

### 2.7 整体校验

校验规则：

- Flow 非空、flowId 非空、stages 非空；
- Stage 非空、stageId 非空、stageId 全局唯一、stage order 不冲突；
- executionMode 必填、stageTimeoutMillis 不得为负、nodes 非空；
- Node 非空、nodeId 非空、nodeId 在 Flow 内全局唯一、同 Stage node order 不冲突；
- nodeType 必填、timeoutMillis 不得为负；
- 最后调用对应 NodeExecutor 的类型专属校验。

`aggregatePolicy=null` 继续按现有行为默认为 PRIORITY；version=0 允许用于草稿模拟。

### 2.8 FirstTerminal 聚合

按已排序的 NodeResult 顺序选择第一个 `stop=true` 的结果：

- 该结果有 decision 时采用该 decision，否则为 PASS；
- reason 采用终止节点 reason；
- 无终止节点时返回 PASS；
- totalScore 与 hitNodes 仍统计全部已执行结果。

### 2.9 OpenRuleEngine Facade

`OpenRuleEngine` 默认装配：

- `OperatorNodeExecutor`；
- `PriorityAggregator`；
- `FirstTerminalAggregator`；
- Java 21 virtual-thread executor；
- FlowCompiler、NodeRunner、Serial/Parallel StageExecutor、FlowExecutor。

Facade 提供 `validate`、`compile`、执行 Definition、执行 CompiledFlow，并实现 `AutoCloseable`。Builder 支持增加自定义 NodeExecutor/DecisionAggregator，以及注入调用方管理的 ExecutorService。

## 3. 分阶段执行与 Review 门禁

### 阶段 A：回归测试固化

- 新增 Parallel ABORT、skip=false、deep immutable、compiled snapshot、完整校验、FirstTerminal、Facade 和 1000 次并发确定性测试。
- Review：测试必须分别对应 roadmap 验收项，禁止只测实现细节。

### 阶段 B：Core 架构调整

- 下沉 FlowCompiler；重构 CompiledFlow/Stage/Node；NodeRunner 去 Registry；新增 Facade。
- Review：`openrule-core` 不得新增 Spring/Jackson/JDBC 依赖；Spring 中不得残留 Compiler 实现。

### 阶段 C：正确性修复

- 修复 ABORT、skip=false、facts/definition 快照、校验和 FirstTerminal。
- Review：异常传播、线程中断、任务取消、稳定 merge 顺序逐项检查。

### 阶段 D：集成与最终验收

- 更新 Spring 自动装配、Service、Loader、测试和 Demo。
- 运行 Core、Spring/API/JDBC 全 reactor。
- 显式运行 `*IT` 并记录运行或跳过状态。
- 最终 Review：检查 diff 范围、公共 API、依赖方向、测试数和 Git 工作区。

## 4. 非目标

- 不实现 ScoreThreshold、ScoreCard、DecisionTable、DecisionTree、RuleSet。
- 不修改 JDBC 草稿/发布生命周期、Flyway、checksum 读取或缓存。
- 不增加 Redis、Micrometer、CI、Enforcer 或 Failsafe；这些属于 R0/M2c。
- 不修改现有 REST 协议。
