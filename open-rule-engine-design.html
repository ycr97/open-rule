01 / SCOPE

定位与边界

开源版聚焦执行内核的架构正确性：把并发模型、SPI 扩展、FailPolicy 治理做扎实。平台级能力（场景路由、不可变发布包、灰度回测）属于企业版范围，但所有接口为其预留扩展点，升级不需要重构内核。

OpenRule 开源版

KERNEL — 本文档范围
  • Flow / Stage / Node 线性执行内核（串行 + 并行）
  • NodeExecutor SPI：validate / compile / execute 三阶段
  • NodeResult 隔离合并 — 并行正确性核心设计
  • FailPolicy 节点级异常治理（SKIP / REVIEW / REJECT / ABORT）
  • 决策聚合器（优先级 / 评分阈值，可自定义）
  • 10 种节点：运算符 / Java / 三语言脚本 / 评分卡 / 决策表 / 决策树 / 规则集 / 子流程
  • 流程版本管理 + checksum 轻量可复现
  • Caffeine 编译缓存 + Redis Pub/Sub 热更新
  • 异步执行日志 + Micrometer 指标

企业版（预留，不在本文档）

04 / EXECUTION

执行模型：并行正确性设计

这是整个引擎最关键的设计。并行节点禁止直接写共享上下文——所有写入封装在 NodeResult.outputs 返回，由合并线程按节点定义顺序单线程合并，保证结果确定性（与完成顺序无关）。

图 3 · 并行 Stage 四阶段时序 — 并发执行、单线程合并、聚合唯一写

🔒
为什么不直接用 ConcurrentHashMap 解决并发写？ConcurrentHashMap 只保证不崩溃，不保证语义正确：两个并行节点写同一个 key、或并发调用 stop() 产生竞态时，结果取决于线程调度，每次执行可能不同。NodeResult 隔离 + 按 order 合并让相同输入永远产生相同输出——这是决策引擎可审计、可回放的前提。
05 / GOVERNANCE

NodeRunner：节点级治理

所有节点执行的唯一入口。超时控制、FailPolicy 异常治理、计时、skipped 判断全部收敛在这一层，各 NodeExecutor 只写纯业务逻辑、不吞异常。

07 / RUNTIME

多语言脚本运行时

三语言统一脚本协议：注入 facts / vars / result，脚本向 result 写出 {hit, decision, stop, reason, outputs}。引擎只解析协议，不关心语言。

Groovy · JVM 原生

缓存 Class 而非 Script 实例（实例非线程安全），每次执行 newInstance + 独立 Binding。SecureASTCustomizer 黑名单：System / Runtime / Thread / ClassLoader。加载时预编译，编译错误在发布前暴露。

Class缓存AST沙箱热路径2-15ms

JS · GraalVM

Context 非线程安全 → ThreadLocal 隔离。沙箱全关：allowAllAccess(false) + HostAccess.NONE + IOAccess.NONE。ES2022 完整支持，通过 test262 套件，生产成熟。

ThreadLocal全沙箱ES2022

Python · 进程池

Jython 停在 2.7、GraalPy 不支持 C 扩展——numpy/sklearn 场景唯一可靠方案是 CPython 常驻进程池。池大小=CPU 核数（GIL），JSON line IPC，异常进程销毁重建绝不回池。

09 / OPERATIONS

缓存的是 CompiledFlow 编译产物（脚本已编译、决策表已索引），不是 JSON。版本切换 = enabled 指针原子切换 + Pub/Sub 广播失效，全集群秒级生效、零重启。

10 / EXTENSIBILITY

NodeExecutor SPI：三阶段扩展协议

新增任何节点类型 = 实现一个接口 + 注册一个 Bean。validate 在保存时拦截配置错误，compile 在加载时完成重活，execute 只做纯执行——错误尽早暴露，运行时尽可能快。

public interface NodeExecutor {
    NodeType supportType();
    default void validate(NodeDefinition node)  // 保存时 · 配置校验，失败阻止保存
    default CompiledNode compile(NodeDefinition node)  // 加载时 · 脚本编译/索引构建，随缓存复用
    NodeResult execute(DecisionContext ctx, CompiledNode compiled)  // 运行时 · 纯执行，禁写 context
}

新增节点类型的全部工作量

① 在 NodeType 枚举加一个值　② 新建一个 Executor 类实现三个方法　③ 注册为 Spring Bean（@Component）。Registry 构造时自动收集——现有代码零改动。前端按 nodeType 动态渲染配置面板。

企业版在同一 SPI 上叠加

模型节点（MODEL）、DAG 决策流（DAG_FLOW）都是新的 NodeExecutor 实现；Scene 路由是 Service 层包装；发布包是 FlowLoader 的另一个实现。内核 SPI 一个字不改。
